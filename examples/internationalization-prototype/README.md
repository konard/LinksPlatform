# Platform.Data Internationalization (i18n) Prototype

This directory contains a proof-of-concept implementation for **Issue #157: Internationalization for error messages** in Platform.Data.

## 📋 Overview

This prototype demonstrates how to add multilingual support to Platform.Data exception messages using .NET's built-in resource management system (.resx files).

## 🎯 Objectives Completed

- ✅ **Engine/Core**: Implemented core internationalization infrastructure using .NET ResourceManager
- ✅ **Russian**: Maintained existing Russian error messages
- ✅ **English**: Added English translations for all error messages

## 🏗️ Architecture

### Resource-Based Approach

The solution uses .NET's standard resource file system:

1. **DataExceptionMessages.resx** - Default/fallback language (English)
2. **DataExceptionMessages.ru.resx** - Russian translations
3. **DataExceptionMessages.Designer.cs** - Auto-generated resource accessor class

### How It Works

```csharp
// The ResourceManager automatically selects the appropriate resource file
// based on Thread.CurrentThread.CurrentUICulture

// English (default)
Thread.CurrentThread.CurrentUICulture = CultureInfo.GetCultureInfo("en");
throw new ArgumentLinkDoesNotExistsException<int>(42);
// Message: "The link [42] passed as an argument does not exist."

// Russian
Thread.CurrentThread.CurrentUICulture = CultureInfo.GetCultureInfo("ru");
throw new ArgumentLinkDoesNotExistsException<int>(42);
// Message: "Связь [42] переданная в качестве аргумента не существует."
```

## 🔧 Implementation Steps for Platform.Data Repository

To apply this solution to the actual `linksplatform/Data` repository:

### 1. Add Resource Files to the Project

Add the following files to `csharp/Platform.Data/Exceptions/`:
- `DataExceptionMessages.resx`
- `DataExceptionMessages.ru.resx`

### 2. Configure .csproj

Ensure the `.csproj` file includes:

```xml
<ItemGroup>
  <EmbeddedResource Update="Exceptions\DataExceptionMessages.resx">
    <Generator>ResXFileCodeGenerator</Generator>
    <LastGenOutput>DataExceptionMessages.Designer.cs</LastGenOutput>
  </EmbeddedResource>
</ItemGroup>

<ItemGroup>
  <Compile Update="Exceptions\DataExceptionMessages.Designer.cs">
    <DesignTime>True</DesignTime>
    <AutoGen>True</AutoGen>
    <DependentUpon>DataExceptionMessages.resx</DependentUpon>
  </Compile>
</ItemGroup>
```

### 3. Generate Designer Class

The `DataExceptionMessages.Designer.cs` file can be auto-generated by:
- **Visual Studio**: Right-click on `.resx` file → Run Custom Tool
- **Command Line**: Use `resgen` or the .NET SDK build process

### 4. Update Exception Classes

Replace the existing exception classes with the internationalized versions provided in this prototype.

### 5. Test

Run the `ExampleUsage.cs` to verify that:
- English messages display correctly
- Russian messages display correctly
- Fallback to English works for unsupported languages

## 🌍 Adding New Languages

To add support for additional languages:

1. **Create a new resource file**: `DataExceptionMessages.{language-code}.resx`
   - Example: `DataExceptionMessages.es.resx` for Spanish
   - Example: `DataExceptionMessages.de.resx` for German

2. **Copy all keys from the default resource file** and translate the values

3. **No code changes required** - the ResourceManager will automatically load the appropriate resource file based on `CurrentUICulture`

## 📊 Comparison: Before vs After

### Before (Hardcoded Russian)
```csharp
private static string FormatMessage(TLink link)
    => $"Связь [{link}] переданная в качестве аргумента не существует.";
```

**Problems:**
- ❌ Hardcoded Russian text
- ❌ No way to change language
- ❌ Not accessible to non-Russian speakers
- ❌ Difficult to maintain multiple translations

### After (Internationalized)
```csharp
private static string FormatMessage(TLinkAddress link)
    => string.Format(DataExceptionMessages.ArgumentLinkDoesNotExist, link);
```

**Benefits:**
- ✅ Supports multiple languages via resource files
- ✅ Automatic language selection based on user's culture
- ✅ Easy to add new languages without code changes
- ✅ Maintains existing Russian messages
- ✅ Adds English support
- ✅ Follows .NET best practices

## 🚀 Performance Considerations

- Resource files are **compiled into satellite assemblies** at build time
- ResourceManager **caches loaded resources** for performance
- String lookups are **very fast** (dictionary-based)
- **No runtime overhead** compared to hardcoded strings
- Uses `MethodImplOptions.AggressiveInlining` for optimal performance

## 📝 Standards and Best Practices

This implementation follows:
- ✅ **.NET globalization best practices**
- ✅ **Standard .resx file format**
- ✅ **ISO 639-1 language codes** (en, ru, etc.)
- ✅ **Existing Platform.Data code style** (AggressiveInlining, pragma warnings)
- ✅ **Backward compatibility** (all existing constructors preserved)

## 🎓 Usage Example

```csharp
using System;
using System.Globalization;
using System.Threading;
using Platform.Data.Exceptions;

// Set user's preferred language
Thread.CurrentThread.CurrentUICulture = CultureInfo.GetCultureInfo("ru");

// Exception message will be in Russian
throw new ArgumentLinkDoesNotExistsException<int>(42, "linkId");
// Output: Связь [42] переданная в аргумент [linkId] не существует.

// Switch to English
Thread.CurrentThread.CurrentUICulture = CultureInfo.GetCultureInfo("en");

// Exception message will be in English
throw new ArgumentLinkDoesNotExistsException<int>(42, "linkId");
// Output: The link [42] passed in argument [linkId] does not exist.
```
