# Удалённый вызов процедур через хранилище Дуплетов

## Аннотация

Этот документ описывает универсальный подход для реализации удалённого вызова процедур (RPC) и вызова методов классов между различными языками программирования с использованием хранилища Дуплетов в качестве среды синхронизации и коммуникации. Решение позволяет любому языку программирования вызывать функции/методы на любом другом языке через стандартизированный протокол на основе Связей.

## Введение

### Постановка проблемы

Современные программные системы часто требуют взаимодействия компонентов, написанных на разных языках программирования. Традиционные решения включают:
- Специфичный для языка FFI (Foreign Function Interface)
- gRPC/Protocol Buffers
- REST API
- Очереди сообщений

Каждое имеет ограничения:
- **FFI**: Специфичен для языка, сложное управление памятью
- **gRPC/REST**: Сетевые издержки, сложность сериализации
- **Очереди сообщений**: Требуют отдельную инфраструктуру

### Предлагаемое решение

Использовать хранилище Дуплетов в качестве универсальной среды межъязыковой коммуникации. Дуплеты естественным образом представляют отношения и могут кодировать:
- Сигнатуры методов
- Аргументы
- Возвращаемые значения
- Состояния вызовов

## Основные концепции

### 1. Дуплеты как универсальная модель данных

Хранилище Дуплетов состоит из связей с двумя ссылками (Начало → Конец). Эта простая структура может представлять:
- **Типы**: `СвязьТипа → СвязьИмениТипа`
- **Методы**: `СвязьИмениМетода → СвязьСигнатурыМетода`
- **Аргументы**: Последовательности связей аргументов
- **Результаты**: `СвязьВызова → СвязьРезультата`

### 2. Представление вызова метода

Вызов метода в Дуплетах состоит из:

```
СвязьВызова:
  Начало: СвязьОпределенияМетода
  Конец: СвязьПоследовательностиАргументов

СвязьОпределенияМетода:
  Начало: СвязьЦелевогоОбъекта (или null для статических)
  Конец: СвязьИмениМетода

СвязьПоследовательностиАргументов:
  Последовательность СвязейАргументов используя балансированный вариант
```

### 3. Состояния синхронизации

Каждый вызов имеет состояние, представленное как связь:
- **Ожидание**: Вызов создан, ожидает выполнения
- **Обработка**: Исполнитель принял вызов
- **Завершено**: Результат доступен
- **Ошибка**: Произошла ошибка

## Архитектура

### Обзор компонентов

```
┌─────────────────┐         ┌─────────────────┐
│   Вызывающий    │         │   Исполнитель   │
│  (Любой язык)   │         │  (Любой язык)   │
└────────┬────────┘         └────────┬─────────┘
         │                           │
         │  1. Создать связь вызова  │
         ├──────────────────────────►│
         │                           │
         │  2. Ожидать результат     │
         │  3. Опрос или подписка    │
         │◄──────────────────────────┤
         │                           │
         │  4. Прочитать результат   │
         │◄──────────────────────────┤
         │                           │
┌────────▼───────────────────────────▼─────────┐
│    Хранилище Дуплетов (Общее)               │
│  - Определения вызовов                       │
│  - Реестр методов                            │
│  - Отслеживание состояния                    │
│  - Результаты                                │
└──────────────────────────────────────────────┘
```

### Диаграмма потока

1. **Фаза регистрации**
   - Исполнитель регистрирует доступные методы
   - Создаёт связи ОпределенияМетода

2. **Фаза вызова**
   - Вызывающий создаёт СвязьВызова с методом + аргументами
   - Устанавливает состояние в Ожидание

3. **Фаза выполнения**
   - Исполнитель мониторит вызовы в состоянии Ожидание
   - Обновляет состояние на Обработка
   - Выполняет метод
   - Сохраняет результат
   - Обновляет состояние на Завершено/Ошибка

4. **Фаза возврата**
   - Вызывающий получает результат
   - Опционально очищает связи вызова

## Спецификация протокола

### Структура связей

#### Связи системы типов

```
// Примитивные типы
СвязьТипаЦелое: [МаркерТипа → "Integer"]
СвязьТипаСтрока: [МаркерТипа → "String"]
СвязьТипаБулево: [МаркерТипа → "Boolean"]
СвязьТипаДробное: [МаркерТипа → "Float"]

// Сложные типы
СвязьТипаМассив: [МаркерТипа → СвязьТипаЭлемента]
СвязьТипаОбъект: [МаркерТипа → СвязьОпределенияКласса]
```

#### Регистрация метода

```
СвязьРегистрацииМетода:
  Начало: ПоследовательностьИмениМетода (напр., "ВычислитьСумму")
  Конец: СвязьСигнатурыМетода

СвязьСигнатурыМетода:
  Начало: ПоследовательностьТиповПараметров
  Конец: СвязьТипаВозврата

// Пример: int ВычислитьСумму(int a, int b)
ВычислитьСумму → [
  [ТипЦелое, ТипЦелое] → ТипЦелое
]
```

#### Вызов метода

```
СвязьВызова:
  Начало: СвязьМетаданныхВызова
  Конец: СвязьСостоянияВызова

СвязьМетаданныхВызова:
  Начало: СвязьРегистрацииМетода
  Конец: ПоследовательностьАргументов

СвязьСостоянияВызова:
  Начало: МаркерСостояния (Ожидание/Обработка/Завершено/Ошибка)
  Конец: СвязьРезультата (null если не завершено)
```

### Переходы состояний

```
Ожидание → Обработка → Завершено
                     ↓
                   Ошибка
```

Каждый переход состояния создаёт новую связь, сохраняя историю.

## Руководство по реализации

### Для авторов языковых привязок

Чтобы реализовать поддержку RPC на языке:

1. **Слой подключения**
   ```
   - Подключиться к хранилищу Дуплетов (файл или сеть)
   - Инициализировать LinksConstants
   ```

2. **Маппинг типов**
   ```
   - Сопоставить типы языка со СвязямиТипов Дуплетов
   - Реализовать сериализацию/десериализацию
   ```

3. **API вызывающего**
   ```
   - Метод: СоздатьВызов(имяМетода, аргументы[])
   - Метод: ОжидатьРезультат(связьВызова, таймаут)
   - Метод: ПолучитьРезультат(связьВызова)
   ```

4. **API исполнителя**
   ```
   - Метод: ЗарегистрироватьМетод(имя, сигнатура, обработчик)
   - Метод: ОбработатьОжидающиеВызовы()
   - Метод: СохранитьРезультат(связьВызова, результат)
   ```

### Пример: Вызывающий на C#

```csharp
// Инициализация
var links = new UnitedMemoryLinks<ulong>("rpc.links");
var rpc = new DoubletsRPC(links);

// Вызов удалённого метода
var call = rpc.CreateCall("ВычислитьСумму", 10, 20);
var result = rpc.WaitForResult<int>(call, timeout: 5000);
Console.WriteLine($"Результат: {result}"); // 30
```

### Пример: Исполнитель на Python

```python
# Инициализация
links = DoubletsLinks("rpc.links")
rpc = DoubletsRPC(links)

# Регистрация метода
@rpc.register("ВычислитьСумму")
def вычислить_сумму(a: int, b: int) -> int:
    return a + b

# Обработка вызовов
rpc.process_pending_calls()
```

## Формат сериализации

### Примитивные типы

- **Целые**: Прямая связь к значению (малые числа) или последовательность цифр
- **Строки**: Unicode-последовательность используя существующую UnicodeMap
- **Булево**: Маркерные связи True/False
- **Дробные**: Представление IEEE 754 как последовательность байтов

### Сложные типы

- **Массивы**: Последовательность связей элементов
- **Объекты**: Карта пар ключ-значение как последовательности связей
- **Null**: Специальная МаркернаяСвязьNull

## Преимущества

1. **Языково-агностичный**: Любой язык с привязками Дуплетов может участвовать
2. **Сеть не требуется**: Может работать с файловым или отображаемым в память хранилищем
3. **Типобезопасный**: Типы сохраняются в хранилище
4. **Инспектируемый**: Все вызовы видимы в хранилище для отладки
5. **Персистентный**: История вызовов сохраняется
6. **Расширяемый**: Легко добавлять новые типы и методы

## Соображения производительности

### Стратегии оптимизации

1. **Пулинг вызовов**: Повторное использование связей вызовов
2. **Индексирование состояний**: Индекс по состоянию для быстрого поиска ожидающих вызовов
3. **Кэширование результатов**: Кэш часто вызываемых методов
4. **Пакетная обработка**: Обработка нескольких вызовов вместе
5. **Отображение памяти**: Использование файлов, отображаемых в память, для низкой задержки

### Бенчмарки (оценочные)

- Издержки локального вызова: ~10-100 микросекунд
- Издержки сетевого вызова: ~1-10 миллисекунд (зависит от метода синхронизации)
- Пропускная способность: ~10,000-100,000 вызовов/секунду (оптимизировано)

## Варианты использования

1. **Микросервисы**: Языково-агностичная коммуникация сервисов
2. **Системы плагинов**: Загрузка плагинов на разных языках
3. **Научные вычисления**: Вызов Python из C++ и наоборот

5. **Интеграция legacy**: Мост между старыми и новыми системами

## Соображения безопасности

1. **Контроль доступа**: Реализовать идентификацию вызывающего
2. **Белый список методов**: Ограничить вызываемые методы
3. **Валидация входных данных**: Проверять аргументы перед выполнением
4. **Ограничения ресурсов**: Предотвратить истощение ресурсов
5. **Аудит логирования**: Отслеживать все вызовы для анализа безопасности

## Будущие расширения

1. **Поддержка Async/Await**: Неблокирующие вызовы
2. **Потоковая передача**: Поддержка передачи больших данных
3. **События**: Шаблон публикация-подписка
4. **Транзакции**: Многовызовые транзакции
5. **Распределённость**: Множественные узлы хранилища

## Сравнение с существующими решениями

| Характеристика | Doublets RPC | gRPC | REST | FFI |
|----------------|--------------|------|------|-----|
| Поддержка языков | Универсальная* | Многие | Универсальная | Специфичная |
| Сетевые издержки | Опциональные | Требуются | Требуются | Нет |
| Типобезопасность | Сильная | Сильная | Слабая | Сильная |
| Сложность настройки | Низкая | Средняя | Низкая | Высокая |
| Производительность | Высокая | Средняя | Низкая | Наивысшая |
| Отладка | Легко | Средне | Легко | Сложно |
| Персистентность | Встроенная | Нет | Нет | Нет |

*Требуется языковая привязка для Дуплетов

## Заключение
